= bifrostlink
:order: 7

`pds2-specializer-bifrostlink` describes RPC services of
https://github.com/CertainLach/BifrostLink[bifrostlink]:

[source,pds]
----
namespace(remowt) {
    service(Pty) {
        request(open_shell, id: 1, cancel: true) {
            field(tunnel) => TunnelAddr;
            field(term) => pstring(Count: varint);
        } => ShellId;
        notification(exited, id: 3, blocking: true) {
            field(id) => ShellId;
        };
    };
};
----

A `request` answers with the type after `=>` (nothing for none), a
`notification` never answers. The block of either holds the fields of a
protodef `container`, so `container` has to be declared. Every method needs an
`id`, unique within its service: it is sent as a varint after the service id,
the first 4 bytes (big endian) of the SHA3-256 of the service's full name
(`remowt::Pty`). Two services of one schema with the same id fail to generate.
`cancel: true` lets the caller abort a running request, `blocking: true` makes
the receiver handle the notification before reading further messages.

Each method becomes a namespace with the types `Request` and, when it answers,
`Response`, so a method body has to qualify its own types named `Request` or
`Response`. The service's `mod.rs` then holds:

[cols="1,3"]
|===
| Item | Is

| `SERVICE_NAME`, `SERVICE_ID` | the full name and its id
| `method::OPEN_SHELL` | each method's id
| `Server<C>` | a trait with a method per request and notification, taking the sender and the request's fields; `register_endpoints(self, &rpc)` serves it
| `Client<C>` | built from a `Remote<C>`, sends requests and notifications
|===

Generated code expects the crate to provide `pds` as bifrostlink's runtime
(`pub mod pds { pub use bifrostlink::pds::*; }`).

`resource => T` is a `bifrostlink::Resource<T>`: a value whose cleanup runs
where it came from once its receiver drops it. It can't be cloned or compared,
so every type holding one derives only `Debug`, and views can't include it.

`pipe` is a `bifrostlink::Pipe`: a byte stream offered by the sender and
connected by the receiver over a transport bifrostlink sets up. It is move-only
like `resource`.

`result(Ok: T, Err: E)` is a `std::result::Result<T, E>`, sent as a `u8` tag
(0 for `Ok`, 1 for `Err`) and the value, so a method can answer with an error of
its own besides the transport error of `Client` calls. It needs the `u8` native.

== TypeScript

A service also generates `service.ts` next to its method namespaces, re-exported
from the namespace `mod.ts`: `SERVICE_NAME`, `SERVICE_ID`, `method` (ids as
`bigint`), a `Server<A>` interface whose methods take the sender and the whole
request object (requests also get an `AbortSignal`), `register_endpoints(server,
rpc)` and a `Client<A>` class. Client methods take the request object, except
for requests without fields, and requests take an optional `AbortSignal`.
Generated code imports `Rpc`, `Remote`, `Call`, `Resource`, `Pipe` and the
`resource`/`pipe` helpers from `pds.ts`, which re-exports
`@deltarocks/bifrostlink/pds`. `resource => T` is a `Resource<T>`, `pipe` a
`Pipe`, and `result` is `{ kind: "ok"; value: T } | { kind: "err"; value: E }`.
