= Definitions
:order: 5

== `def(name) { ... } => <type>`

Declares a named type. The pre-rocket block holds *type parameters* and
*arguments*; the post-rocket value is the type body.

[source,pds]
----
def(radiationGuard) {
    type(Value);
} => container {
    field(a) => Value;
};

def(sized) {
    argument(length);
} => array(length: ./$length) => u8;
----

`argument(name) => <type>` declares the argument's type instead of inferring it
from its uses. A literal argument is constructed as that type, any other value
must already have it:

[source,pds]
----
def(choice) {
    argument(kind) => u8;
} => union(tag: ./$kind) {
    variant(one, match: 1) => u8;
};

def(fixed) => choice(kind: 1);
----

The declared type may be a type parameter. A use-site that doesn't bind it takes
it from the argument's value when that value has a written type, i.e. contains
a cast, so `terminated(end: u8(0))` is short for `terminated(End: u8, end: 0)`:

[source,pds]
----
def_native(terminated) {
    type(Value);
    type(End);
    argument(end) => End;
    body;
};
----

== `namespace(name) { ... }`

Groups definitions under a path prefix.

[source,pds]
----
namespace(protocol) {
    def_native(u8);
    def(msg) => container { field(op) => u8; };
};
----

Outside, the contents are addressed as `root::protocol::u8`.

== `package(name) { ... }`

A namespace that is also a unit of output. Packages are declared at the top
level only. Without `--crates` they generate like namespaces; with `--crates
NAME` every package becomes the crate `NAME-<package>` (underscores turned into
dashes), everything outside packages goes to `NAME-root`, and the crate `NAME`
re-exports them all. The `@!doc` of a package describes its crate.

`--module PACKAGE=PATH` writes a package into an existing crate instead, as the
module file `PATH` (or `PATH/mod.rs` when `PATH` is a directory): no manifest,
`crate::` is the crate the module belongs to, and other packages are reached
through the `NAME` crate. Its types live in the module too, so nothing outside
the package may use them; a type outside packages that uses one moves into the
module with it. This places custom definition output, see
xref:../specializers/libraries.adoc#custom-definitions[Custom definitions], and
the types it lowers to, in a crate of your own.

== `include("file.pds")`

Replaced by the statements of `file.pds`, a path relative to the including
file. The included file's `@!` attributes go to the enclosing block, unless it
sets them itself:

[source,pds]
----
package(v1_8) {
    @!doc "Minecraft 1.8 protocol types"
    include("pds/1.8.pds");
};
----

Includes are expanded when a schema is read from a file, in any block, and may
nest; a file including itself, directly or not, is an error. `pds2 format`
leaves them as written.

== Deduplicated packages

`@!deduplicate true` at the top of a schema merges definitions that packages
share. A definition of a package that an earlier package (in declaration order)
already has under the same path, with the same text and referencing equal
definitions, becomes an exported alias of that earlier one, and references in
the definitions that stay point straight at the first package having them.
Definitions on a reference cycle are equal only when the whole cycle is.
`def_native`s move out of the packages to the same path at the top level, so
every package has to declare them identically. Named arguments compare
regardless of their order.

[source,pds]
----
@!deduplicate true

package(v1) { def(id) => u8; def(entry) => container { field(id) => id; }; };
package(v2) { def(id) => u8; def(entry) => container { field(id) => id; }; };
----

Here `v2::id` and `v2::entry` become aliases of `v1::id` and `v1::entry`, and
the generated `v2` crate re-exports them.

== Generics

Type parameters are introduced with `type(Name)` in a `def` block and consumed
by name within the body. They are passed at use sites as named item arguments:

[source,pds]
----
def(wrapper) {
    type(Value);
} => container {
    field(inner) => Value;
};

def(use) => container {
    field(w) => wrapper(Value: u8);
};
----

Type defaults are written `type(Name) => <type>`:

[source,pds]
----
def_native(mymap) {
    type(Key);
    type(Value);
    type(Size) => vu32;
};
----
